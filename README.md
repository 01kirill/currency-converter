# Currency Converter

Сервис обмена валют по официальным курсам Национального банка Республики Беларусь.

Что умеет:

- раз в сутки загружает курсы НБ РБ: сразу при старте и затем после каждой полуночи по Минску. Загрузка идемпотентна;
- обменивает валюты в два этапа: сначала выдаёт котировку (сумма в целевой валюте, курс, id сделки), затем клиент подтверждает или отклоняет сделку;
- строит отчёт по принятым сделкам за период: сколько каждой валюты пришло в кассу и ушло из неё, сколько было сделок;
- показывает список незавершённых сделок.

Описание API находится в [`API.md`](API.md). Интерактивная документация доступна после запуска: `http://localhost:8000/docs` (Swagger) и `http://localhost:8000/redoc`.

## Хранилище: PostgreSQL

Курсы и сделки хранятся в PostgreSQL 18. Почему именно он:

- **Идемпотентная загрузка курсов** обеспечивается самой базой: первичный ключ `(currency_code, rate_date)` и `INSERT ... ON CONFLICT DO NOTHING`. Повторная загрузка или одновременный запуск нескольких экземпляров сервиса не создаёт дублей.
- **Точные деньги.** Суммы и курсы хранятся в `NUMERIC`, без потерь точности, как у `float`.
- **Транзакции и блокировки.** Подтверждение сделки читает её через `SELECT ... FOR UPDATE`: два одновременных запроса не могут решить одну сделку дважды.
- **Отчёт считается одним SQL-запросом** (`UNION ALL` + `GROUP BY`) по частичному индексу принятых сделок, без загрузки всех сделок в приложение.
- **Целостность на уровне БД:** `CHECK`-ограничения на статус сделки и положительную сумму.

Схема создаётся миграциями Alembic (`alembic/versions/`). В Docker они применяются автоматически при старте.

## Запуск через Docker

Нужны Docker и Docker Compose.

```bash
git clone https://github.com/01kirill/currency-converter.git
cd currency-converter
cp .env.example .env
docker compose up --build -d
```

Перед первым запуском на любой машине, кроме своей, замените `POSTGRES_PASSWORD` в `.env`:
пароль применяется только при создании базы, поменять его потом можно лишь пересоздав базу
(`docker compose down -v`, данные удалятся). Порт PostgreSQL опубликован только на `127.0.0.1`
и из сети недоступен.

Что произойдёт:

1. Поднимется PostgreSQL (`db`). Данные хранятся в volume `pgdata` и переживают перезапуск.
2. Когда база готова (healthcheck), стартует сервис (`api`): применяет миграции, запускается на порту `8000` и сразу загружает курсы на сегодня.
3. Документация API откроется по адресу `http://localhost:8000/docs`.

Логи: `docker compose logs -f api`. После старта в них должна появиться строка вида `Rates loaded: 30 new` (при повторном запуске в тот же день — `0 new`).

Остановка: `docker compose down`. Чтобы удалить и данные: `docker compose down -v`.

### Переменные окружения

Все настройки читаются из `.env` (шаблон — `.env.example`).

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `POSTGRES_USER` | — | пользователь БД |
| `POSTGRES_PASSWORD` | — | пароль БД, в `.env.example` заглушка `change-me` |
| `POSTGRES_DB` | — | имя базы |
| `POSTGRES_HOST` | `localhost` | хост БД; в Docker compose подставляет `db` |
| `POSTGRES_PORT` | `5432` | порт БД |
| `NBRB_BASE_URL` | `https://api.nbrb.by` | адрес API НБ РБ |
| `NBRB_TIMEOUT_SECONDS` | `10` | таймаут запроса к НБ РБ |
| `RATES_RETRY_SECONDS` | `600` | пауза перед повторной загрузкой курсов после ошибки |
| `LOG_LEVEL` | `INFO` | `DEBUG`, `INFO`, `WARNING` или `ERROR` |

## Локальный запуск без Docker

Нужны Python 3.14 и [uv](https://docs.astral.sh/uv/). PostgreSQL удобнее всё равно поднять в Docker.

```bash
cp .env.example .env
uv sync
docker compose up -d db
uv run alembic upgrade head
uv run uvicorn app.main:app --reload
```

## Тесты и линтеры

```bash
docker compose up -d db
docker compose exec db createdb -U app currencies_db_test   # один раз
uv run pytest
uv run ruff check . && uv run ruff format --check . && uv run mypy
```

- `tests/unit` — домен, use cases на fake-адаптерах, клиент НБ РБ (`httpx.MockTransport`), планировщик. Не требуют БД и сети.
- `tests/integration` — репозитории и Unit of Work на настоящем PostgreSQL, включая проверку блокировки сделки.
- `tests/e2e` — сценарии через HTTP: создать сделку → она в незавершённых → подтвердить → она в отчёте, а также коды ошибок.

Integration- и e2e-тесты используют отдельную базу `<POSTGRES_DB>_test` и очищают её после каждого теста. Если PostgreSQL не запущен или нет `.env`, они пропускаются.

Перед каждым коммитом pre-commit запускает ruff, mypy (strict) и unit-тесты: `uv run pre-commit install`.

## Архитектура

Слои по Clean Architecture, зависимости направлены только внутрь:

```
src/app/
├── domain/          правила обмена: Deal, ExchangeRate, расчёт кросс-курса, доменные ошибки
├── application/     сценарии (use cases), порты (Protocol) и DTO
├── infrastructure/  PostgreSQL (SQLAlchemy), клиент НБ РБ (httpx), часы, планировщик, настройки
├── presentation/    HTTP API на FastAPI: роутеры, схемы, перевод ошибок в коды ответа
├── dependencies.py  сборка use cases из реализаций портов
└── main.py          создание приложения и жизненный цикл ресурсов
```

`domain` и `application` не импортируют ни FastAPI, ни SQLAlchemy, ни httpx и тестируются без них.

## Принятые решения

- **Курс считается через BYN:** `курс(A → B) = (курс A / scale A) / (курс B / scale B)`. BYN поддерживается как обычная валюта с курсом 1.
- **Используются только курсы на сегодня** (дата по Минску). Если они ещё не загружены, создание сделки отвечает `503`, а не берёт вчерашние.
- **Курс фиксируется в сделке** при её создании, подтверждение использует его.
- **Округление:** сумма к выдаче — 2 знака после запятой, `ROUND_HALF_UP`; курс — 10 значащих цифр. Сумма в запросе — не больше 2 знаков после запятой.
- **У котировки нет срока жизни:** незавершённая сделка ждёт решения клиента.
- **Решение по сделке принимается один раз.** Повторное подтверждение или отклонение отвечает `409`.
- **Отчёт учитывает только принятые сделки** и фильтрует их по дате принятия (`resolved_at`) в часовом поясе Минска; границы периода включительно. Отклонённые и незавершённые деньги кассу не двигали.
- **Сделка учитывается в отчёте в обеих валютах:** исходная валюта «пришла в кассу», целевая «ушла из кассы». Поэтому сумма `deals_count` по всем строкам вдвое больше числа сделок.
- **Расписание загрузки курсов:** при старте и в 00:05 по Минску (запас на расхождение часов). При ошибке — повтор через `RATES_RETRY_SECONDS`.
- **Деньги в JSON передаются строками** (`"89.16"`), чтобы клиент не терял точность на `float`.
